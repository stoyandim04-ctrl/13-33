# 13:33 — Digital Studio

Сайтът на 13:33: React + TypeScript + Tailwind CSS v4 (shadcn-съвместима структура).

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # проверка на TypeScript + production build в dist/

npm run typecheck
npm run media      # прерисува постерите/видеата на концептуалните проекти
```

## Какво е адаптирано спрямо оригиналните компоненти

**Horizon** — запазени: звездите, мъглявината, четирите релефа, атмосферата, bloom, плавната камера, интрото с разделени символи. Променени: цветовете (синьо #5B7CFA, ледено #A8D8FF, графитени силуети); един hero и един преход вместо HORIZON/COSMOS/INFINITY; локален прогрес на секцията (ScrollTrigger, вързан към hero-то); отделни refs за всеки текст; пълно освобождаване на ресурсите; по-лека сцена на телефон (по-малко звезди, по-слаб bloom, по-нисък pixel ratio, разширен FOV за портретен екран); статичен хоризонт без WebGL; неподвижен кадър при reduced motion; three.js се зарежда асинхронно.

**WorksWheel** — запазени: геометрията, пръстенът, който се отваря в перспективна спирала, един rAF проход, easing, culling, индексът. Променено: колелото следва скрола на собствената си секция (sticky сцена) вместо да прихваща `wheel` събития — hero-то и колелото имат отделни участъци от страницата и не се борят за един жест; touch скролът е естествен; след последния проект страницата продължава. `WHEEL_UNITS = 550` px скрол на проект, `DRAG_UNITS = 320` px дърпане/плъзгане на проект. Докато сцената е закачена, един жест с колелце/тракпад или един свайп сменя точно един проект (инерцията не прескача); над пръстена и след последния проект жестът остава на страницата. При скрол с лентата или клавиатурата колелото се установява в посоката на движение (12% стигат). Добавени: постер + видео (всеки видим прозорец пуска своето видео, докато секцията е на екрана), клик/Enter отваря проекта, страничен прозорец или индекс го избира, дърпане не отваря линк, клавиатура (↑ ↓ Home End).

## Материали за замяна

1. **Проекти.** В портфолиото са Obsidian, Strong Muse, Варовик, Black Clove и Цукиби — всички са **концепции на 13:33**, направени като истински сайтове (означени „Концепция“ навсякъде). Постерите и видеата се записват от самите сайтове: `npm run media:live` (`scripts/build-live-media.mjs`, адресите са вътре; Варовик е в клона `varovik`) и `scripts/build-tsukibi-media.mjs` за **Цукиби** (`sites/tsukibi/`). По-старите мокъп концепции (`scripts/concept-mocks.mjs`) вече не са в колелото. За реален проект: добави запис в `src/data/projects.ts` със `status` (`live`, `in-progress`, `prototype`, `own-product`) и сложи в `public/projects/<slug>/`:
   - `poster.webp` — 1450×1000 (съотношение 1.45);
   - `preview.mp4` (H.264) и `preview.webm` (VP9) — 6–10 s, без звук. Настройките на ffmpeg са в `scripts/build-concept-media.mjs`;
   - `liveUrl` — само ако сайтът е публичен и клиентът е съгласен.
   Кандидатите от Notion (VELION LAB, INTNS / FitCheck, Strong Muse) не са добавени, докато нямат потвърден линк, запис, статус и разрешение.
2. **Имейл за контакт** — `VITE_CONTACT_EMAIL` (бизнес имейлът още не е решен).
3. **Текстове за потвърждение** — обещанията в контактната секция („Четем всяко запитване лично“, „Първият разговор е … без ангажимент“) и бюджетните диапазони във формата.
4. **Лого** — засега знакът е типографският „13:33“; favicon-ът е временен.

## Интеграции, които изискват настройка

Копирай `.env.example` в `.env.local`. Всичко с префикс `VITE_` отива в браузъра — **никога не слагай ключове там**.

- **Запитвания** — Supabase проект „13-33“ (`fuqixmjvsalzemxrbslp`, Франкфурт). Таблиците са в `supabase/migrations/`; RLS е включен без политики, така че само сървърът (с service-role ключа) стига до данните. Клиентът няма акаунт — отваря страницата си с таен линк `/zapitvane/<token>`.
- **AI консултантът** — `api/ai.ts`, Claude (`claude-opus-5-5`). Свободен разговор само за сайтове и дигитални проекти, отговорите се изпращат като поток (text/plain), на езика на клиента (BG/EN). Когато има достатъчно, сам пита за име и имейл и извиква инструмента `finish_inquiry` — сървърът създава запитването и потокът завършва с ред `[[inquiry:<token>]]`, който страницата превръща в линка на клиента. Гледа снимки и PDF и никога не казва цена, срок или размер на капарото. Без `ANTHROPIC_API_KEY` чатът задава четири кратки въпроса сам и завършва с формата за контакт. Плаща се от предплатен кредит в platform.claude.com.
- **Капарото** — по вид проект, в `DEPOSITS` (`src/lib/inquiry-shared.ts`); 0 означава „не е зададено“ и клиентът вижда брифа без стъпка за плащане. Плаща се през **Stripe Checkout** (`api/pay.ts`): `STRIPE_SECRET_KEY`, а за webhook-а `STRIPE_WEBHOOK_SECRET` (събитие `checkout.session.completed` → `https://<сайт>/api/pay?webhook`). И без webhook страницата сама проверява сесията, когато клиентът се върне от Stripe.
- **Имейли до клиента** — Resend (`RESEND_API_KEY`, `MAIL_FROM` на потвърден домейн, по желание `MAIL_REPLY_TO`): „брифът е при нас“ с линк към страницата и „капарото е получено“. Без ключ не се пращат.
- **Панелът** — `/studio`, вход с `STUDIO_PASSWORD`. Вижда всичко, сменя етапа; на клиента се пише по имейл.
- **Известия на телефона** — по желание, Telegram бот (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`): ново запитване (целият бриф, имейл, телефон), съобщение, приета оферта, среща; снимките и файловете на клиента идват след него като документи в пълно качество (`notifyFiles`); и клик върху главните бутони (`api/ping.ts` + `src/lib/ping.ts`; бутонът се отбелязва с `data-ping`, всеки клик идва веднъж на посещение, панелът `/studio` не праща).
- **Настройки във Vercel** (Settings → Environment Variables) — всички имена са в `.env.example`. Задължителни: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `ANTHROPIC_API_KEY`, `STUDIO_PASSWORD`; за плащане `STRIPE_SECRET_KEY` (+ `STRIPE_WEBHOOK_SECRET`); за имейли `RESEND_API_KEY`, `MAIL_FROM`; `SITE_URL` — публичният адрес (digistudio13.com). Локално: `vercel dev` (обикновеният `npm run dev` не пуска `/api`).
- **Хостинг** — SPA; `vercel.json` пренасочва маршрутите (без `/api`) към `index.html`.
