# 03 · Claude Code — промптове

Промптовете по-долу са работни. Никакви непотвърдени бизнес решения да не се представят като окончателни. Започваме с прототип, не с production e-commerce.

## Prompt 1 — дизайн концепция и прототип

```
You are a senior brand designer, UX strategist and frontend engineer. Build a responsive, premium, mobile-first concept for the Bulgarian women's fitness brand STRONG MUSE. Do not invent commercial facts.

Brand name: STRONG MUSE.
Exact copy: "СИЛАТА Е В ТЕБ. ДАЙ И ДВИЖЕНИЕ !" and "Бъди своето вдъхновение".
Proposed program cards:
- MUSE START · 4 седмици — Влез в ритъм
- MUSE STRONG · 6 седмици — Надгради силата и навиците си
- HIIT VIBES AT HOME — Твоята тренировка. На твоя терен.
- STRONG MUSE COACHING — Индивидуален подход с мен

Reference: the client likes a FITQUEEN Linktree landing page with bold hero photography and product cards, but wants a distinct, more premium original execution. Do not copy third-party images or exact composition.
Available assets: two food-related PDFs; new professional photos are pending. Use graceful placeholders until licensed images are provided.
Design: feminine strength, elegant editorial typography, intentional whitespace, visually striking hero, premium cards, accessible contrast, polished subtle motion, fast page speed.
Build homepage concept with navigation: Начало, За мен, Програми, Хранене, Контакт; program cards must not claim programs are already available. Add no fake testimonials, fake credentials, fake countdown timers, fake pricing, or working payment claims.
First provide proposed information architecture and visual tokens, then implement a modular prototype. Show mobile and desktop previews. Do not implement Stripe, member accounts or checkout yet.
```

## Prompt 2 — продуктов каталог след одобрение

```
Extend the existing STRONG MUSE website with data-driven product cards. Separate states: AVAILABLE, COMING_SOON, INQUIRY_ONLY. Only list items as available after explicit confirmation. Structure content so price, subtitle, image, duration, CTA destination, and delivery type are editable. Do not process payments, expose PDF files publicly, or email files before a separately approved payment/delivery specification.
```

## Prompt 3 — спецификация за плащане (само ако Анна избере директни продажби)

```
Before writing code, ask for the selected payment provider, merchant setup, pricing, tax/legal policies, digital goods delivery rules, cancellation/refund requirements, email provider, and whether accounts are needed. Propose an architecture for server-side checkout, signed/verified webhooks, authenticated delivery or expiring links, security controls and test cases. Do not use fake payment success states or ship to production without end-to-end sandbox tests.
```

## След одобрение се добавят

- Финален дизайн system и промпт за отделните страници.
- Одобрени текстове, снимки и програми.
- Реални компоненти за каталог/коучинг.
- QA checklist, accessibility, SEO, analytics, responsive tests.
- Production deployment prompt — само след финално решение за платежния модел.
